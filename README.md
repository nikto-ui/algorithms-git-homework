# Git: задачи, ветки и коммиты

## Какие задачи решает Git

Git — распределённая система контроля версий. Она сохраняет историю изменений файлов проекта и помогает вернуться к прежнему состоянию, сравнить версии и понять, кто и когда внёс изменения.

Git позволяет нескольким участникам работать над одним проектом: каждый может вести изменения отдельно, а затем объединить их. Если изменения в одних и тех же строках несовместимы, Git сообщает о конфликте, который нужно разрешить вручную. Репозиторий можно хранить локально и синхронизировать с удалённым сервером, например GitHub.

Git — это инструмент контроля версий, а GitHub — сервис для размещения репозиториев и совместной работы с ними.

## Что такое коммит

**Коммит** — сохранённый снимок отслеживаемого состояния проекта. У него есть уникальный идентификатор, автор, дата и сообщение, описывающее изменения. Коммиты образуют историю: обычно каждый коммит ссылается на предыдущий, а коммит слияния может иметь несколько родителей.

Чтобы создать коммит, сначала выбирают изменения командой `git add`, затем сохраняют их командой `git commit`:

```bash
git add README.md
git commit -m "Добавить ответы на вопросы о Git"
```

## Что такое ветка

**Ветка** — подвижная ссылка на коммит. Обычно основная ветка называется `main`; отдельную ветку можно создать для новой задачи или исправления. Новые коммиты передвигают текущую ветку вперёд, не меняя другие ветки. Готовые изменения можно объединить с основной веткой с помощью слияния (`merge`).

Например:

```bash
git switch -c feature/readme  # создать ветку и перейти в неё
# изменить файл, добавить его и создать коммит
git switch main               # вернуться в основную ветку
git merge feature/readme      # объединить изменения
```

Локальный репозиторий можно связать с удалённым и отправить туда коммиты:

```bash
git remote add origin https://github.com/ИМЯ_ПОЛЬЗОВАТЕЛЯ/ИМЯ_РЕПОЗИТОРИЯ.git
git push -u origin main
```
